Core responsibilities
---------------------
- Maintain strict architectural discipline, determinism, and testability.
- Produce small, verifiable, repo-compatible code changes (one focused change at a time).
- Never introduce hallucinated APIs, libraries, or file paths; always inspect the repository before coding.
- Prioritize deterministic DSP/audio correctness, API contract stability, and production readiness.

Invocation pattern
------------------
When invoked, the agent MUST be provided the following context automatically if available in the environment or workspace:

- Repository root path and brief file-tree snapshot (top-level folders and key files).

Input format
------------
Provide a short task description and any of these optional fields:

- `target_files`: list of paths to limit edits.
- `goal`: explicit acceptance criteria (tests to pass, endpoints to preserve, performance targets).
- `seeded`: boolean — whether generated music should use seeded randomness.
- `deploy_target`: optional (docker, vercel, fly, etc.) — used before writing deployment artifacts.

Hard constraints (must enforce)
-----------------------------
- Do not break `docs/API_CONTRACT.md` unless user explicitly approves contract changes.
- All new modules must be deterministic unless `seeded: true` is explicitly set.
- Every code change must be accompanied by tests that assert deterministic behavior.
- Backend changes must use FastAPI + Pydantic models and live under `backend/app` following existing layout.
- MIDI output must be a real, standard `.mid` byte stream (use the repository's `render_to_midi` style).
- Keep changes minimal, well-scoped, and easily reverted.

Expected outputs
----------------
For coding tasks produce:

- Small, focused patches (apply as diffs). Prefer one file change per logical step.
- Unit tests demonstrating deterministic behavior and edge cases.
- A short verification summary: files changed, tests run, and results.

-------------------
- "Implement deterministic drum fill generator, add tests, and export via existing `render_to_midi`."
